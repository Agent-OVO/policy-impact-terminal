审计日期：2026年7月10日。
审计对象：现有20份人工政策报告。
审计目的：验证阶段七原文版本事实源，并区分“官方原文是否完整可靠”和“报告中的政策原文摘录是否可逐字定位”两个问题。

| 类型 | 数量 |
|---|---:|
| 逐字或规范化后完整匹配 | 41 |

## 三、迁移处置

本次存量迁移坚持零正文变化：

- 不自动重写上述7份报告；
- 不为提高匹配率删除合理证据；
- 不用模型重新生成整份报告；
- 不阻断不可变修订体系的技术迁移；
- 将原有payload及其内容哈希原样保存，以便后续修订差异可审计。

这7份报告迁入后应保留证据治理标记，只有在单份报告发生正常增量修订时，才按受影响字段进行纠正。

## 四、后续修订规则

从下一份新报告和下一次相关修订开始：

1. `evidence.excerpt`必须是可在原文中定位的逐字摘录，或明确标识的删节摘录；
2. 人工概括、政策含义和产业解释应写入`interpretation`，不得伪装成原文；
3. 多处原文合并时，应拆成多个证据项，或在字段中标明“综合摘录”及来源位置；
4. 附件证据必须保留附件URL、页码和附件哈希；
5. 报告发布前运行官方原文摘录审计；
6. 低于既定定位阈值时进入人工复核，不自动调用模型重写全文。

## 五、自动化入口

官方复合原文抓取：

```bash
npm run stage7:source-fetch -- --require-all
```

证据摘录审计：

```bash
npm run stage7:evidence-audit
```

本地详细审计文件位于被忽略路径：

```text
artifacts/stage7/official-source-documents.json
artifacts/stage7/source-evidence-audit.json
artifacts/stage7/source-evidence-audit.md
```

这些文件含完整官方原文和详细摘录，不进入Git；Git仅保存审计结论、方法和治理规则。

## 六、结论

官方原文版本事实源已经具备20/20覆盖和完整附件处理能力，可以支持阶段七不可变原文迁移。现有报告证据摘录存在7份需治理的历史债务，但不应与原文来源完整性混为一谈，也不应借迁移机会机械重写报告。最稳妥的处理是：原样迁移、登记债务、在后续单份增量修订中按字段纠正。
