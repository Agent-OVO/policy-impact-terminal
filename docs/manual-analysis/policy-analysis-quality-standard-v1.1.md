# 政策产业影响分析质量标准 v1.1

## 一、这份标准解决什么问题

本系统已经能够完成“政策抓取—人工分析—校验—发布—前端展示”。下一阶段的重点不是多写报告，而是确保报告不会让用户误解。

本标准要解决的核心问题是：

> 把“政策产业链相关”讲清楚，避免被误读成“政策点名受益”“确定利好”或“投资建议”。

## 二、报告发布前必须坚持的四条底线

### 1. 不把方向相关写成确定受益

可以写：

- 与政策方向相关；
- 属于产业链观察对象；
- 需要等待地方项目、预算、招标或配套细则验证。

不能写：

- 确定受益；
- 必然受益；
- 直接利好；
- 推荐买入；
- 目标价；
- 收益承诺。

如果政策没有点名企业、没有订单、没有采购、没有补贴，就不能让前端看起来像“确定受益股清单”。

### 2. 公司映射必须分层

每个公司必须被归入以下层级之一：

| 层级 | 含义 | 展示口径 |
|---|---|---|
| policy_named | 政策点名或附件列示 | 可显示“官方点名”，但仍不是投资建议 |
| direct_industry | 直接产业链环节 | 可显示“直接产业链相关” |
| indirect_industry | 间接产业链环节 | 必须显示“间接证据” |
| thematic_only | 主题相关 | 只作为观察线索 |
| watch_only | 低置信观察 | 应弱化展示或放入低频观察 |

### 3. 公司分数必须拆成两个维度

以后不能只给一个“置信度”。必须拆成：

| 字段 | 含义 |
|---|---|
| policyRelevance | 公司业务与政策方向是否匹配 |
| evidenceCertainty | 政策文本能否直接支撑这个公司映射 |

例如，一个新能源公司可能与政策方向高度相关，但政策没有点名公司，也没有订单，则应写成：

```json
{
  "policyRelevance": 86,
  "evidenceCertainty": 45,
  "confidence": 62
}
```

这表示：方向相关，但证据不直接。

### 4. 证据摘录和人工解释必须分开

证据摘录应尽量接近政策原文。

建议结构：

```json
{
  "excerpt": "政策原文短摘",
  "interpretation": "人工解释",
  "sourceLocation": "第二部分第（三）项"
}
```

不能用人工概括冒充原文摘录。

## 三、公司分数降级规则

### 1. 证据等级与置信度上限

| evidenceLevel | 含义 | confidence 上限 |
|---|---|---:|
| strong | 政策点名、附件列示、明确项目或直接条款 | 100 |
| indirect | 产业链相关，但没有点名公司 | 74 |
| pending | 主题相关或待验证 | 64 |

### 2. 证据确定性上限

| evidenceLevel | evidenceCertainty 建议上限 |
|---|---:|
| strong | 90 |
| indirect | 60 |
| pending | 45 |

### 3. 规划类政策的公司数量

国务院规划、部门规划类政策通常不应列太多公司。

建议：

- 普通规划类：公司不超过 6 个；
- 产业链特别清晰的政策：最多 8 个；
- 超过 8 个必须给出充分理由。

## 四、前端展示规则

### 1. 公司卡片必须提示边界

公司卡片上应优先显示：

- 未点名；
- 无订单证据；
- 无采购证据；
- 产业链相关；
- 间接证据；
- 待地方项目验证。

不要只突出分数。

### 2. 公司详情页必须先讲不确定性

公司详情页顶部应显示：

> 该公司未被政策点名，当前仅为产业链相关观察；具体影响需等待地方项目、预算、招投标或配套细则验证。

### 3. 公司矩阵必须真实表达两个维度

横轴：政策相关度。  
纵轴：证据确定性。

如果没有显式填写两个字段，系统应按证据等级自动降级，而不是把两个维度都等同于总置信度。

## 五、横向对比规则

如果没有真实调用历史政策库，不得写“相比此前政策更强”“延续上一轮政策”等比较性判断。

允许写：

> 本报告未启用横向对比，仅基于当前政策文本进行首轮结构化分析。

## 六、允许无公司映射

部分政策不适合映射上市公司。系统应允许：

```json
{
  "companies": [],
  "analysisCoverage": {
    "companyImpactConclusion": "本政策不适合映射具体公司。"
  }
}
```

不能为了前端好看硬凑公司。

## 七、报告回炉优先级

### 第一优先级

1. 碳达峰行动方案；
2. 人工智能＋人社；
3. 城市更新规划。

原因：公司映射较强、用户更容易误读为受益清单。

### 第二优先级

1. 高质量数据集建设；
2. 教育发展规划；
3. 就业优先规划。

原因：商业化边界和公司映射需要更谨慎。

### 第三优先级

1. 应急体系规划；
2. 农业农村现代化规划；
3. 美丽中国建设规划。

原因：整体风险较低，但仍需补强横向对比和证据摘录。

## 八、执行顺序

1. 先增强发布前校验规则；
2. 再修前端公司卡片和公司详情页；
3. 然后回炉修订高风险报告；
4. 最后恢复新增政策分析。

## 九、最终口径

本系统不是荐股系统，而是政策产业影响分析系统。

前端和报告都必须持续提醒：

> 公司映射仅代表政策链条相关性，不代表政策点名、订单、补贴、采购或业绩影响，不构成投资建议。
