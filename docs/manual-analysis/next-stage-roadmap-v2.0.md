## 三、阶段三：B类方向化迁移

### 目标

完成剩余两份B类报告：

- 就业优先战略“十五五”规划；
- 教育发展“十五五”规划。

完成后：

```text
已完成五模块迁移：15 → 17
B类待办：2 → 0
```

### 方法

默认要求：

```text
policyIndustryMap
industryChain
policyNetwork
investmentDirection
```

具体公司只有同时满足以下条件才进入 `companyMap`：

- 业务暴露可以由年报、公告、项目或官方产品材料证明；
- 政策传导不超过两层；
- 可以写清最低补证条件和风险边界。

公共就业、教育公益服务和政府平台属性必须前置说明。允许 `companyMap=[]`。

### 验收标准

- 不出现泛人力资源或泛教育概念股清单；
- 区分公共服务主体、技术服务商和商业平台；
- 地方预算、采购、数据合规和应用效果成为主要催化与风险；
- 原报告事实和证据摘录完整保留。

## 四、阶段四：生产运营与视觉验收

### 1. CI与发布门禁

将以下步骤固化为发布门禁：

```text
MANUAL_QUALITY_STRICT=true npm run manual:validate
npm run manual:test
npm run build
git diff --check
```

要求新报告、回炉报告和精简字段报告均进入回归集。

### 2. 进度与质量指标

持续记录：

- 严格失败数；
- 已迁移报告数；
- 独立公司证据映射数；
- `pending/watch_only`映射数；
- 写回和Pages部署成功率；
- 登录后视觉验收覆盖率。

### 3. 登录后视觉验收

在具备安全测试账号或可清理登录态后检查：

- 桌面端和移动端公司排序；
- 政策关系与监管角色标签；
- 政策网络链接；
- 长文本换行和空模块；
- 浏览器控制台错误；
- 旧报告兼容展示。

### 4. 证据更新机制

- 记录公司证据年度；
- 新年报只更新业务暴露和风险，不自动上调政策关系；
- 地方名单、招标或合同出现后才允许上调 `pending`；
- 保留历史来源、版本和更新时间。

## 六、阶段切换规则

- 阶段三完成后才能将报告迁移工作转为常态生产；
- 新的高时效政策可插入单份分析，但完成后必须回到当前阶段；
- 技术债只有在阻断发布时才允许提前处理；
- 公司排序始终只代表研究排队，不构成交易结论。
