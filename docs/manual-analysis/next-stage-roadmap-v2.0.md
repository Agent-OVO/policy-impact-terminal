## 三、当前常态运行任务

内容迁移不再作为主线。后续报告按照生产手册逐份执行：

```text
官方原文与附件
→ 政策、产业、公司、项目证据分层
→ 严格校验
→ 回归测试
→ 治理指标
→ 人工写回
→ Pages部署
→ 线上抽查
```

持续维护指标：

- 报告和治理注册表一致性；
- 证据对象覆盖率；
- 独立公司证据覆盖率；
- pending/watch_only数量；
- 写回成功率和Pages部署成功率；
- 认证后视觉抽查覆盖率。

## 五、阶段切换与插入规则

允许高时效政策插入单份分析，但完成后回到当前主阶段。

禁止：

- 因指标压力硬凑公司证据；
- 为提高覆盖率删除合理的待验证主体；
- 将政策行业证据冒充公司业务证据；
- 将技术债与多份政策内容回炉混成同一提交；
- 跳过全量质量门直接发布。

## 六、阶段七、八生产候选形成后的当前下一步

2026年7月11日，阶段六至阶段八已经完成零费用仓库级封板：不可变原文和报告修订、关系投影、事务发布与回滚、Token硬预算、邀请制账户治理、两阶段硬删除和三个管理员专用Edge候选入口均通过本地PostgreSQL、表级RLS、Deno、工作流和20份真实影子包回归。实施结果见`docs/architecture/stage-8-final-regression-report-v1.0.md`。

用户明确不接受任何额外费用。当前优先级调整为：

1. 不创建Supabase Preview Branch、新项目或其他付费资源，持续执行本地高保真迁移、RLS和Edge质量门；
2. 使用受保护的只读入口导出生产`full_text`，与20份官方复合原文形成差异报告，不以旧生产文本自动覆盖官方完整来源；
3. 使用既有数据库连接制作本地AES-256-GCM加密逻辑备份，并完成恢复验证；当前PITR关闭且物理备份列表为空，备份门尚未通过；
4. 重新执行`npm run production:readiness:audit`，只有`productionWriteReady=true`且阻断项为0，才可申请生产加法影子迁移授权；
5. 生产影子迁移后仍不切换前端和旧写回，先验证真实Auth、RLS、PostgREST、三个候选Edge入口和20份新旧对照；
6. 随后改造人工写回链，并分离`analyze`中的禁用规则引擎；
7. 固定四来源，完成有限采集和来源健康治理；
8. 通过SQL、RPC、CLI和JSON形成公司反查、产业聚合、时间线和观察池；
9. 内核与生产治理稳定后再整体重构前端。
