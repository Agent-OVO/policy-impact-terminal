## 三、当前常态运行任务

内容迁移不再作为主线。后续报告按照生产手册逐份执行：

```text
官方原文与附件
→ 政策、产业、公司、项目证据分层
→ 严格校验
→ 回归测试
→ 治理指标
→ 人工写回
→ Pages部署
→ 线上抽查
```

持续维护指标：

- 报告和治理注册表一致性；
- 证据对象覆盖率；
- 独立公司证据覆盖率；
- pending/watch_only数量；
- 写回成功率和Pages部署成功率；
- 认证后视觉抽查覆盖率。

## 四、下一主阶段：独立技术债治理

技术债必须与政策内容变更分开提交。

### 优先级1：GitHub Actions运行时升级

目标：消除官方Action被强制从Node.js 20迁移到Node.js 24的提示。

工作：

- 核对checkout、setup-node、configure-pages、upload-pages-artifact和deploy-pages最新版；
- 升级后验证Pages、人工写回和质量工作流；
- 不在同一提交修改政策报告。

### 优先级2：前端代码拆分

当前主JavaScript包约593KB。

目标：

- 按工作台、报告模块、管理模块拆分；
- 降低首屏下载和解析成本；
- 保持旧报告和移动端功能不回归。

### 优先级3：依赖安全

- 执行npm audit；
- 修复可安全升级的高危漏洞；
- 对无法升级项形成书面风险接受；
- 不以破坏构建或运行兼容为代价强制升级。

### 优先级4：认证后生产QA

具备安全测试身份后：

- 逐份打开17份完整报告；
- 验证公司排序、关系标签、政策网络来源和移动端长文本；
- 检查3份C类轻量报告无空白或错误模块；
- 记录生产控制台和网络请求。

## 五、阶段切换与插入规则

允许高时效政策插入单份分析，但完成后回到当前主阶段。

禁止：

- 因指标压力硬凑公司证据；
- 为提高覆盖率删除合理的待验证主体；
- 将政策行业证据冒充公司业务证据；
- 将技术债与多份政策内容回炉混成同一提交；
- 跳过全量质量门直接发布。
