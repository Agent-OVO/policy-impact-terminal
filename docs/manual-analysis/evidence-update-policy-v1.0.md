# 政策报告证据更新规则 v1.0

## 一、适用范围

本规则适用于所有已发布人工政策报告的公司业务证据、地方落实证据、项目证据和政策关系等级更新。

## 二、证据分层

1. **政策动作证据**：政策正文、官方附件、正式名单、监管公告。
2. **产业节点证据**：政策明确提出的行业、技术、项目、标准、监管和资金方向。
3. **公司业务证据**：公司年报、招股书、交易所公告、官方产品材料和经核验的重大合同。
4. **项目兑现证据**：中标公告、合同、项目验收、地方实施名单、补贴或采购结果。

政策动作证据不得直接替代公司业务证据。政策写明某一产业方向，不等于该产业中的任一公司获得订单。

## 三、年度报告更新

- 新年度报告发布后，可以更新公司的业务暴露、产品、客户结构、收入占比和风险。
- 仅凭新年报不得自动上调政策关系等级。
- 年报只证明“公司做什么”，不证明“公司获得当前政策项目”。
- 更新时必须保留证据年度、公告日期、页码或章节和原证据边界。

## 四、关系等级上调条件

### `watch_only/thematic_only` → `indirect_industry`

至少满足：

- 公司材料证明存在对应业务；
- 政策传导层级不超过两层；
- 能写出具体补证条件和风险边界。

### `indirect_industry` → `direct_industry`

至少满足：

- 公司已有对应行业或场景业务；
- 地方实施方案、试点、项目库或采购文件明确覆盖该业务；
- 关系不是单纯概念或跨行业类比。

### `direct_industry` → `policy_named`

仅限：

- 政策正文或官方附件直接点名；
- 正式名单、公示结果或明确项目主体文件直接列示。

## 五、关系降级条件

出现以下情况应降级：

- 公司退出相关业务或业务占比显著下降；
- 项目终止、合同取消或长期未形成实施；
- 政策配套规则改变，原有业务不再满足准入；
- 原证据被发现只是媒体推测、集团层面概念或主体归属错误；
- 公司与被点名子公司、制造主体或项目主体不存在可核验归属关系。

## 六、地方落实和项目证据

地方名单、招标、合同或项目验收出现后，更新顺序为：

```text
地方文件或项目原文
→ 核对主体和项目范围
→ 核对上市公司归属
→ 更新 companyMap
→ 保留原政策边界
→ 严格校验和回归测试
```

不得仅依据新闻标题、转载摘要或市场传闻升级关系。

## 七、历史保留

- 不覆盖原始政策事实和原证据摘录。
- 新证据使用新增 `evidence` 项，不复用旧证据ID改写不同事实。
- 每次更新保留 `generatedAt`、证据日期、来源和解释。
- 关系升级或降级必须在提交说明中写明原因。

## 八、发布要求

每次证据更新必须依次通过：

```bash
MANUAL_QUALITY_STRICT=true npm run manual:validate -- manual-reports/*.json
npm run manual:test
npm run manual:metrics
npm run build
```

随后执行单份人工写回并确认 `published: true`，再核对Pages部署和线上页面。
