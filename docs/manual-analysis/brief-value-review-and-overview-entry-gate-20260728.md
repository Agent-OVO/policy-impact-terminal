# 跨政策简报用户价值复核与运营总览准入裁决

日期：2026年7月28日  
版本：v1.0  
复核对象：

- `docs/briefs/energy-manufacturing-policy-mainline-brief-20260728.md`
- `docs/briefs/manufacturing-policy-tools-and-business-realization-20260728.md`
- 生产只读快照 run `30348607783`
- 当前登录后工作台首页及其安全只读数据接口

## 一、裁决

两份跨政策简报通过价值复核，可以作为政策解析终端从“单篇报告生产”转向“主线决策支持”的正式成果。

但简报仍是5—10分钟研究阅读材料，不能替代每天打开终端后1—3分钟完成的运营判断。下一阶段应启动**最小只读运营总览v0.1**，同时继续冻结历史报告数量扩张。

总览v0.1只使用登录态安全读接口和已经人工审定的两份简报，不新增写入权限，不触发自动分析，不把静态材料伪装成实时生产状态。为统一人工处置口径，新增独立的`operations-overview`只读Edge Function；它不改变数据库表、RLS或任何写能力。

## 二、价值评分

| 维度 | 评分 | 结论 |
|---|---:|---|
| 跨政策压缩 | 4/5 | 已把11项能源、制造和保险政策压缩为两条制度链；但两份简报分别约220行和258行，仍需一个更短的入口层。 |
| 判断结构 | 5/5 | 能稳定回答“政策如何连接、成本责任落在哪里、项目怎样形成、经营证据缺什么”。 |
| 证据纪律 | 5/5 | 明确区分方向、名单、项目、合同、交付、收入；没有为提高公司覆盖率降低门槛。 |
| 福建落地 | 4/5 | 已落到输配电价、绿电直连、节能改造、首台套和首批次项目；仍需后续真实省级清单和企业证据。 |
| 日常可操作性 | 2/5 | 简报本身不能直接显示当前窗口、历史积压、最近报告和状态变化，需要总览入口。 |

综合裁决：**研究价值通过，运营入口不足。**

## 三、两份简报真正减少了什么成本

### 1. 减少逐篇政策阅读

第一份简报将可再生能源供给、消费责任、输配电价、绿电直连、零碳工厂、智能工厂、节能监察和长期资产责任放入同一制度链。

第二份简报将强制节能改造、首台套保险补偿和首批次新材料保险补偿放入同一经营兑现链。

用户不再需要先阅读11份完整报告，才能识别以下共同结构：

```text
政策方向
→ 强制责任或项目入口
→ 投资、价格或保险工具
→ 资格、名单和真实用户
→ 合同、交付、保单和资金
→ 收入、利润和现金流
```

### 2. 减少错误公司映射

两份简报均把公司升级门槛固定为：

```text
主题相关
→ 政策点名
→ 项目主体
→ 采购或合同
→ 交付验收
→ 经营兑现
```

这比“按政策主题罗列概念公司”更适合长期生产，也保护了现有companyMap质量。

### 3. 减少福建落地判断的发散

福建观察已被收敛为少数可验证事实：

- 省级节能降碳企业和项目清单；
- 福建差别化电价及实际账单；
- 多用户绿电直连细则和首批项目；
- 零碳工厂、智能工厂推荐名单和总投资；
- 首台套资格、交付、保单和资金项目；
- 首批次新材料最终用户、销售、交付和补助资金。

## 四、为什么不能直接把两份简报搬到首页

简报是研究成果，不是运营状态。直接搬运会产生三个问题：

1. 页面仍然过长，无法在1—3分钟完成判断；
2. 静态简报不能反映当前窗口和历史积压变化；
3. 用户容易把“下一观察事实”误读为已经发生的事实。

首页应只显示状态、主线结论和下一证据，完整逻辑仍留在简报和单项报告中。

## 五、总览v0.1准入范围

### 允许显示

- 14日滚动当前窗口内的待分析政策数量；
- 2026年5月1日以来的历史待分析总量；
- 最近24小时已发布报告和待分析政策的状态变化；
- 最近发布的正式报告；
- 两条已经人工审定的跨政策主线；
- 每条主线下一步最值得等待的事实；
- 数据覆盖是否完整、哪些指标尚未通过安全接口公开。

### 明确不显示

- 自动生成的投资建议；
- 自动公司推荐；
- 未经人工确认的政策结论；
- 伪实时采集健康；
- 证据阻断的内部原因和政策全文；
- 为视觉完整而填充的0值；
- 历史49项逐项清单或清零进度条。

## 六、数据真实性规则

总览v0.1使用以下只读接口：

- 已发布报告：`policies`安全读取；
- 权威运营状态：登录态`operations-overview` Edge Function；
- 兼容回退：`list_pending_policy_analysis`安全RPC；
- 主线和下一观察事实：两份已发布简报的人工审定内容。

`operations-overview`使用服务角色读取生产状态，但先校验普通登录用户令牌，只返回当前窗口、历史队列、证据阻断数量、开放任务数量、最近24小时变化和最多50条列表安全字段。它不返回`full_text`、原始`metadata`或人工阻断原因。

若新函数不可用，页面回退旧RPC并明确标注兼容口径；不得把兼容结果冒充权威人工处置状态。

## 七、总览v0.1成功标准

1. 用户打开首页后10秒内能看出当前窗口是否需要处理；
2. 1分钟内能理解两条政策主线及下一观察事实；
3. 3分钟内能进入最近报告或主线代表报告；
4. 页面不新增写入能力，不启动分析任务；
5. 数据不完整时主动暴露覆盖边界；
6. 移动端不隐藏核心状态和主线；
7. 原有报告列表、待分析清单和单报告页面保持可用。

## 八、后续门槛

总览v0.1上线并经过实际使用后，再决定是否继续扩展只读运营能力，以展示：

- `awaiting_evidence`政策的列表安全原因；
- 定时采集健康与最近有效采集；
- 正式主线简报的版本化数据。

当前v0.1已聚合证据阻断数量、开放任务和陈旧任务数量，但不公开阻断原因。

在实际使用证明必要前，不扩大数据库权限和前端复杂度。
