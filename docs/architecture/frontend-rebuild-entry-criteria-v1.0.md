# 前端整体重构启动条件 v1.0

日期：2026年7月10日。

新前端重构不得仅因旧界面视觉陈旧而启动。以下条件全部满足后，阶段十二才可正式开始。

## 一、数据与版本

- `report_revisions`已部署并成为完整报告权威来源；
- 20份存量报告迁移验收全部通过；
- 当前发布、草稿、历史修订和回滚API稳定；
- 原文版本与报告修订通过哈希关联；
- 旧`metadata.reportPayload`只剩过渡读取，不再承担正式写入。

## 二、跨政策投影

- 公司、产业、政策网络、证据和信号投影可从revision重建；
- 公司反向索引、产业聚合、时间线、关系变化和观察池拥有稳定SQL/RPC契约；
- 所有聚合结果可追溯至revision和evidence；
- 投影一致性测试和漂移检查已进入CI。

## 三、生产链

- 修订发布具备事务、幂等和并发保护；
- Edge Function类型检查和关键集成测试通过；
- 固定四来源的健康监控、降级和告警已运行；
- L0/L1零Token、L2/L3预算门禁和`model_usage_ledger`已生效；
- 备份恢复、发布回滚和来源失败演练完成。

## 四、产品边界

- 邀请制和最小角色已实施；
- 公开注册已关闭；
- 账户停用、删除和使用事件保留规则明确；
- 普通用户、研究生产和系统治理三类任务边界稳定；
- 新前端是否保留头像、通知和行为分析已有明确取舍。

## 五、接口稳定性

- 核心读API至少连续两个发布周期或30天未发生破坏性变化；
- `frontend_contract_version`已建立；
- SQL/RPC、CLI和JSON样例覆盖所有拟建页面；
- 错误、空状态、轻量报告和历史修订契约已定义；
- 在线用户查询不具备模型调用权限。

## 六、设计准备

- 完成用户任务和信息架构评审；
- 确定首页不是生产队列，而是投资观察工作台；
- 确定单政策、产业、公司、观察池和变化事件之间的导航关系；
- 建立设计令牌、组件层级、移动端和可访问性基线；
- 明确新旧前端双轨、切换和回滚方案。

## 七、启动门结论

任一核心条件未满足时，只允许进行低成本的信息架构草图和接口样例，不进入正式页面开发。该门禁用于避免在不稳定内核上再次形成大规模兼容代码和CSS债务。
