# ADR-007 模型调用边界与Token预算治理

状态：已接受
日期：2026年7月10日

## 总原则

系统采用“少采、严筛、深析、复用、增量更新、离线生成、在线零Token、预算可审计”。Token是架构资源，不是操作提醒。

## 零Token环节

以下环节不得调用模型：

- 网页抓取、正文提取、去重和哈希；
- 元数据提取和文档类型初筛；
- L0排除和L1归档；
- 政策列表、搜索和报告浏览；
- 公司反向索引、产业聚合和时间线查询；
- 观察池查询、普通提醒和权限判断；
- 严格校验、质量指标和投影生成。

普通用户打开网页或查询任何既有结果时，在线模型调用必须为0。

## 允许调用的操作

- 高价值政策结构化分析；
- 确定性规则无法解决的疑难政策分类；
- 有证据支撑的关键公司关系研判；
- 证据冲突和边界判断；
- 重大报告修订及变化字段复核。

模型不得替代来源收集、SQL聚合、身份匹配和确定性校验。

## 单任务预算

### 疑难分类

- 仅提交标题、元数据和必要短片段；
- 硬上限2,000 Token；
- 不生成报告。

### L2方向化分析

- 默认一次核心调用；
- 软目标8,000 Token；
- 输入与输出合计硬上限12,000 Token；
- 公司核心映射默认0—4家。

### L3深度分析

- 默认一次核心生成；
- 软目标20,000 Token；
- 全部调用合计硬上限30,000 Token；
- 第二次调用只允许针对反证、边界、一致性或变化字段，禁止重新生成全文；
- 第二次调用自身建议不超过8,000 Token。

预算同时约束原始上下文Token和扣除缓存后的有效计费Token，避免依靠缓存掩盖过长输入。超过硬上限必须停止并由管理员记录例外理由。

## 月度预算

初始月度有效Token硬预算为300,000，70%和90%时告警，达到100%后暂停非紧急模型任务。连续两个月运行后，根据实际L2/L3数量、缓存命中率和研究质量重新校准，不自动上调。

## 调用账本

建立`model_usage_ledger`，至少记录：

- `policy_id`、`revision_id`、`operation_type`；
- 模型和服务商；
- `input_tokens`、`output_tokens`、`cached_tokens`、有效计费Token；
- `budget_class`、预算策略版本和调用时预算快照；
- `trigger_reason`、`prompt_template_version`；
- 输入片段哈希、请求哈希、缓存键；
- 状态、异常和创建时间。

不得记录不必要的密钥或完整敏感请求。账本是成本、复现和异常消耗审计依据。

## 硬门禁

- 调用前预算预检；
- 调用后按服务商实际用量记账；
- 相同输入、模板和模型优先命中缓存；
- 单政策超预算、月度超预算和异常重复调用均阻断；
- 发布门验证报告关联的模型调用已入账；
- 在线查询API不得持有模型调用权限。

## 后果

该决策把模型集中到少量高价值研究判断，并使成本可解释、可复核、可阻断。代价是部分疑难报告需要人工选择片段和分阶段分析，而不能无限扩展上下文。
