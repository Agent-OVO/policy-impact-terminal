# ADR-005 旧前端冻结与最终重构原则

状态：已接受
日期：2026年7月10日

## 决策

旧前端进入冻结维护状态。系统先完成报告版本、投影、来源治理、生产链、跨政策能力和运行治理，再整体设计并重构前端。

## 冻结期允许修改

- 数据显示错误和事实口径错误；
- 安全问题；
- 核心操作阻断；
- 严重可访问性问题；
- 新后端API的最小必要接入；
- 生产兼容和回归修复；
- 为修订、投影和认证契约提供最小端到端验收入口。

## 冻结期禁止事项

- 重新配色、装饰性动画和视觉美化；
- 新卡片体系或大规模CSS整理；
- 在旧信息架构中继续堆叠公司聚合、产业聚合、观察池等正式复杂页面；
- 为尚未稳定的API制作长期UI；
- 以拆文件为名进行无验收目标的大规模重构。

## 内核验收方式

阶段七至阶段十一优先通过以下方式交付：

- SQL迁移与数据库约束；
- RPC/API契约；
- CLI和JSON输出；
- 自动化单元、集成和迁移测试；
- 修订差异、投影一致性和回滚演练；
- 旧前端的最小兼容读取。

冻结不等于完全不接入。只要新后端契约需要生产验证，可以增加薄适配层，但不得把薄适配层演变为新产品页面。

## 重构原则

新前端不是旧页面换皮，而是围绕以下任务重新设计：

1. 政策信号总览；
2. 产业—政策聚合；
3. 公司—政策反向索引；
4. 关系变化、证据到期和反证事件；
5. 观察池；
6. 单政策报告及修订历史；
7. 研究生产和系统治理的独立管理入口。

## 后果

该决策避免在不稳定内核上重复建设页面，并控制巨型`App.tsx`和`styles.css`继续膨胀。短期内部分新能力只通过CLI或API可见，这是有意的阶段性取舍。
