# ADR-008 原文、证据卡和增量分析复用原则

状态：已接受
日期：2026年7月10日

## 决策

建立有限、按需、可失效的复用层，减少重复读取和重复模型分析，但不建设通用政策语料平台或全市场公司数据库。

## 原文复用

每个政策原文版本保存：

- 规范化正文和原始来源；
- `source_document_hash`；
- 获取时间、发布时间和解析器版本；
- 稳定段落ID、段落顺序和段落哈希；
- 与附件或补充文件的关系。

模型输入优先引用稳定段落ID和必要片段，不反复提交整篇原文。正文哈希未变化时，不因重复抓取触发重新分析。

## 结构化摘要缓存

允许缓存政策动作、主体、时间、金额、名单、约束和实施条件等结构化中间结果。缓存必须关联原文哈希、提取器版本和模式版本；任一关键版本变化时重新验证。

中间摘要不是发布结论，不能绕过报告审核。

## 公司证据卡

仅在以下情形建立：

- 同一公司出现在两份及以上报告；
- 公司属于用户明确观察对象；
- 单次业务关系核验成本较高；
- 证据将在后续关系升级、降级或反证中重复使用。

证据卡只保存：

- 公司稳定身份与证券标识；
- 一条可核验业务事实或项目事实；
- 来源、发布日期、摘录、定位和内容哈希；
- 适用范围、证据等级、观察时间和失效时间；
- 不能据此推出的结论。

不得复制完整年报，不把估值、财务全量、行情和泛公司画像纳入本模块。证据卡是研究缓存，不是公司主数据仓库。

## 增量修订

新证据进入后：

1. 通过稳定实体键定位受影响公司、产业或政策关系；
2. 比较证据卡和当前修订；
3. 只创建受影响字段的修订差异；
4. 复用未变化的原文段落、中间摘要和证据卡；
5. 必要时调用模型审查变化片段；
6. 重新运行确定性全量校验和投影。

## 失效与边界

- 原文段落、摘要和证据卡均带版本与哈希；
- 超过有效期或来源被替换时标记过期，不自动删除历史引用；
- 报告引用过期证据时进入复核队列；
- 同一证据在不同政策中的解释可以不同，证据卡不保存统一投资结论。

## 后果

系统可以显著降低重复上下文和重复核验成本，同时避免演变为大型外部数据平台。代价是需要稳定实体键、段落索引和证据过期治理。
