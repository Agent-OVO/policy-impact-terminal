# 政策解析终端生产变更控制规则

状态日期：2026-07-16  
适用对象：GitHub Actions、Supabase Edge Functions、数据库、密钥、账号、生产报告和运行调度

## 一、基本原则

1. 默认只读。没有显式写入参数时，生产配置脚本不得修改远程资源。
2. 用户控制研究启动，Agent承担研究执行。定时采集不得自动分析、自动映射公司或自动发布报告。
3. 单一真实缺陷只做最小修复。不得借修复扩建无关字段、页面或自动化。
4. 所有生产代码变更使用隔离工作树、独立分支、PR、质量门禁和生产烟测。
5. 数据库结构写入必须先有可恢复备份，并完成本机专用数据库恢复验证。
6. 删除账号、轮换密钥、启用新定时调度、数据库迁移等不可逆或高影响操作必须取得独立用户裁决。

## 二、变更级别

### L0：只读运营检查

包括：

- 读取GitHub Actions运行记录和产物；
- 查询候选收件箱；
- 读取政策正文和附件；
- 生产页面登录态验收；
- 生成运行摘要、迁移计划和审计报告；
- 核对函数版本、报告数量和开放PR。

允许直接执行。不得写数据库或改变状态。

### L1：已授权的日常政策运营

包括：

- 将新候选设置为待判断、等待证据、快速归档或忽略；
- 用户已持续授权范围内，显式启动证据完整且有研究价值的政策分析；
- Agent生成、校验和应用报告；
- 重复采集回归。

必须满足：政策ID明确、原文与附件完整、自动分析选择为0、报告通过严格校验。日常运营不得批量处置历史迁移债务。

### L2：应用、工作流和Edge Function变更

包括：

- 采集器、附件解析、去重、状态投影和生产QA修复；
- GitHub Actions调整；
- Edge Function升级；
- 不改变数据库结构的前后端代码修复。

必须满足：

1. 隔离工作树；
2. 最小差异；
3. 单元测试、合同测试、构建和安全检查通过；
4. 官方Actions固定到完整提交SHA；
5. PR质量门禁通过；
6. 合并后只部署明确需要升级的函数；
7. 生产烟测和回归通过；
8. 状态文档更新。

### L3：高影响生产变更

包括：

- 数据库迁移、删除或批量修改数据；
- 密钥轮换；
- 删除账号；
- 启用新定时调度或补偿调度；
- 开放自动分析、自动发布或自动公司映射；
- 修改生产认证、RLS或管理员权限；
- 新增付费资源。

必须取得用户独立裁决。数据库迁移还必须满足：

- 加密逻辑备份已生成；
- 密文和明文哈希通过；
- 备份在本机专用数据库完成恢复；
- 恢复后关键表和迁移表可查询；
- `artifacts/production-backups/latest-manifest.json`标记`restoreVerified=true`；
- 设置精确确认变量；
- 迁移后执行数据库、Edge、页面和收件箱回归。

## 三、生产配置脚本写入门

`scripts/configure-production.mjs`默认只打印计划，不加载密钥、不连接数据库、不修改远程资源。

显式写入参数：

```text
--apply-functions
--apply-github-secrets
--apply-supabase-secrets
--apply-db-migrations
--dispatch
```

对应确认变量：

```text
PRODUCTION_FUNCTION_DEPLOY_CONFIRMATION=DEPLOY_FUNCTIONS:<project-ref>
PRODUCTION_SECRET_ROTATION_CONFIRMATION=ROTATE_SECRETS:<project-ref>
PRODUCTION_DB_MIGRATION_CONFIRMATION=APPLY_MIGRATIONS:<project-ref>
PRODUCTION_WORKFLOW_DISPATCH_CONFIRMATION=DISPATCH_WORKFLOWS:<project-ref>
```

仅提供参数但没有匹配确认变量时，脚本必须失败。

## 四、回滚和证据

每次L2或L3变更至少保留：

- PR链接和合并提交；
- 变更文件；
- 测试结果；
- 部署运行ID；
- 函数或页面版本；
- 生产烟测结果；
- 回滚目标提交；
- 发现的问题和后续观察项。

数据库变更还要保留备份ID、恢复验证报告和迁移前后行数核对。

## 五、禁止事项

- 在脏工作树中直接推送生产；
- 用手工补跑冒充定时任务连续性；
- 未取完整附件即分析附件型政策；
- 对重复政策覆盖已发布报告；
- 将服务角色密钥写入前端、日志或产物；
- 使用浮动GitHub Action标签；
- 在CI依赖安装阶段执行未经审查的生命周期脚本；
- 未经裁决删除历史账号、批量归档70项历史候选或启用恢复调度；
- 未经恢复验证推送数据库迁移。
