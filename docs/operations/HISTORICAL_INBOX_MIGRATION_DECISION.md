# 历史70项人工候选收件箱迁移裁决说明

状态日期：2026-07-16  
数据来源：生产收件箱自2026-05-01起全量查询，返回70项。

## 一、只读分类结果

| 分类 | 数量 | 含义 |
|---|---:|---|
| 已知本地研究结果，待生产ID对齐 | 7 | 已经研究过，但生产政策ID与本地结果尚未统一，不能直接重复分析 |
| 疑似附件或发布外壳 | 20 | 正文不足1200字，且标题指向规划、办法、名单、目录、项目计划等；需要先用新版PDF/OFD采集复核 |
| 已知快速归档 | 1 | 上海辰山国家植物园批复，已有明确快速归档结论 |
| 真正未审阅历史政策 | 42 | 尚无可复用正式结果，需要做快速价值筛选 |
| 当前窗口新候选 | 0 | 2026年7月15日起的新候选已经处置完成 |

## 二、禁止直接执行的做法

- 不能把70项全部标记为已完成；
- 不能按标题批量生成报告；
- 不能把20项短正文全部机械设为等待证据，必须先让新版附件采集复核；
- 不能把7项本地结果直接套到生产ID，需核对标题、官方来源、正文和结论对象；
- 不能为了清空收件箱分析42项全部历史政策。

## 三、可选方案

### 方案A：保守收口

1. 只处理1项已知快速归档；
2. 对7项已有本地结果逐项完成生产ID对齐；
3. 其余62项维持原状态。

优点：风险最低。  
缺点：历史收件箱仍然很大，无法形成清晰运营入口。

### 方案B：分层收口（推荐）

1. 完成方案A；
2. 使用新版附件采集器重跑20项短正文，能够提取PDF全文的转回待判断，仍缺完整附件的转为等待证据；
3. 对42项真正未审阅政策只做快速价值筛选，不直接形成完整报告；
4. 快速筛选结果只允许：快速归档、等待证据、保留待判断、最多挑选5项进入Agent正式分析；
5. 每批最多处理10项，并保存批次清单和处置理由。

优点：能收口历史债务，同时控制研究量和误判风险。  
缺点：需要多批次运行，不能一次完成。

### 方案C：全量重新研究

对70项逐项重新读取、补证和生成报告。

不推荐。它会把历史清理变成大规模研究扩张，违背当前轻量运营目标。

## 四、建议裁决

建议采用方案B，并明确：

- 7项ID对齐可以复用既有研究，但必须重新校验生产正文；
- 20项附件候选先采集，后处置；
- 42项只做快速筛选；
- 正式分析上限5项；
- 任何批量状态修改前先输出拟处置清单，不直接写库。
