# 政策解析终端安全与治理审计

状态时间：2026-07-16  
审计方式：只读仓库、GitHub管理API、Supabase备份状态、生产账号依赖和自动测试。

## 一、已通过

1. GitHub Actions默认令牌权限为只读，工作流不能批准Pull Request。
2. 每个工作流均显式声明权限。
3. 所有外部Action已固定到完整40位提交SHA。
4. CI依赖安装均使用`npm ci --ignore-scripts`。
5. `.github/CODEOWNERS`覆盖工作流、Edge Functions、数据库迁移和生产配置入口。
6. 受跟踪文件扫描128个，未发现疑似明文凭据。
7. npm高危依赖审计为0。
8. 生产配置脚本默认只读；迁移、函数部署、配置轮换和工作流触发均需显式参数与精确确认变量。
9. 数据库迁移额外要求已通过本机恢复验证的加密逻辑备份。
10. 临时生产QA账号能够自动删除并核对关联表清理。

## 二、尚未通过

### 1. 主分支没有保护规则

- `main`没有Branch Protection；
- 仓库没有Ruleset；
- 仍可能绕过PR和质量门禁直接推送主分支。

### 2. 仓库允许全部GitHub Actions

- `allowed_actions=all`；
- 仓库设置没有强制完整SHA固定；
- 当前代码已固定SHA，但仓库层未阻止后续引入浮动Action。

### 3. 数据库恢复门未建立

- PITR关闭；
- 可列出的物理备份为0；
- 加密逻辑备份尚未生成；
- 本机恢复验证尚未完成；
- 当前环境没有数据库连接凭据。

结论：`productionWriteReady=false`，数据库迁移继续冻结。

### 4. 两个历史测试账号

- 账号A：存在59条用户事件、无分析任务，暂不适合直接删除；
- 账号B：无用户事件、无分析任务，可在用户独立批准后删除。

## 三、已增加的治理能力

- 加密逻辑备份工具；
- 本机专用数据库恢复验证工具；
- 备份加密、篡改、远程恢复目标和确认变量测试；
- 生产写入准备度审计；
- 仓库治理只读审计；
- 受跟踪文件凭据扫描；
- 生产变更控制规则；
- 历史收件箱迁移只读规划；
- 生产运行摘要工作流；
- 漏跑恢复守卫，默认不启用定时。

## 四、需要用户裁决

1. 是否为`main`启用Ruleset：必须经PR、要求`quality`检查通过、禁止强制推送和删除分支，管理员不绕过。
2. 是否限制GitHub Actions来源，并在仓库设置中强制完整SHA固定。
3. 是否建立加密逻辑备份：需要取得或重置数据库密码，并准备本机PostgreSQL或Docker恢复环境。
4. 是否删除无关联数据的旧测试账号；有59条事件的账号应保留、匿名化还是连同事件删除。
5. 是否启用每30分钟恢复检查调度。
6. 历史70项收件箱采用保守收口还是分层收口。
